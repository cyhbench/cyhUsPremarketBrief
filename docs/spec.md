# 規格：美股盤前快報（US Premarket Brief）

依據：[requirement.md](requirement.md)。撰寫日 2026-11-02。

標示說明：**（已驗證）**＝2026-11-02 03:56–03:59 UTC（美東週日 22:56，非盤前時段）在 TG VM 用 Brave 無痕實際打開確認可讀；**（未驗證）**＝尚未實測，實作第一步要測。盤前時段的實際表現全部要在驗收時重測。

---

## 1. 目標

每個 NYSE 交易日，在開盤前 30 分鐘內（美東 09:00–09:30），由 TG VM 上的 AI bot 自動產生一份繁體中文 Markdown 快報，推送到 GitHub，透過 GitHub Pages 靜態網站公開瀏覽；和 `markdownReader`、`qrCodeGenerator` 一樣，點開網址就能看，不需登入或安裝。

## 2. 範圍

### 2.1 做

- **網站**：單一 `index.html`（同既有兩個工具：純前端、零後端、CDN 鎖版本），預設顯示最新一份快報，可切換歷史日期。
- **快報內容**：需求列的 7 項（見第 4 節），外加產生時間與資料來源清單。
- **產生流程**：TG VM 排程 → 包裝腳本判斷交易日 → 呼叫 Claude 產生 → 失敗改呼叫 Codex → 腳本檢查格式 → commit、push。
- **交易日曆**：DST 感知（以 `America/New_York` 時區計算），休市日與早收日照 NYSE 官方公告。

### 2.2 不做

- 不做即時報價、自動刷新、圖表、個股查詢或任何互動分析。
- 不做盤中、收盤或週末報告；休市日不產生報告。
- 不做投資建議、買賣訊號或目標價。
- 不轉載新聞全文，只寫一句話摘要並附原文連結。
- 不使用付費 API 或需要登入的資料來源。
- 不做 Telegram 推播（是否要做見「待使用者決定」第 3 項）。
- 不沿用 skill `us-premarket-briefing` 的 web_fetch 繞路寫法；只取其篩選規則、中文對照表與「抓不到就標示，不得編造」原則。

## 3. 架構與檔案

```
index.html                 檢視器（GitHub Pages 入口）
reports/YYYY-MM-DD.md      每日快報，日期為美東日期
reports/index.json         報告清單（由腳本維護，AI 不碰）
data/nyse-calendar.json    NYSE 休市日與早收日（2026、2027）
prompts/brief.md           給 AI 的產生指示（來源、篩選規則、輸出格式）
bin/run-brief              包裝腳本（Python 標準函式庫，不需 pip 套件）
deploy/                    systemd user service 與 timer 範本
```

- **檢視器**：`marked` 鎖 `4.3.0`（同 markdownReader）。快報內容來自外部網頁經 AI 整理，屬不可信輸入，**原始 HTML 一律跳脫不渲染**，連結只允許 `https:`。手機與桌面都能讀，深色模式跟隨系統。
- **日曆**：從 nyse.com 官方頁抄錄成 `data/nyse-calendar.json`，不依賴 `exchange_calendars` 等套件（TG VM 目前未安裝）。（已驗證）官方頁列有 2025–2027。日曆沒有當年資料時腳本**停止並記錄錯誤**，不猜。
  - 註：舊 skill 的 2026 休市表**漏了 Juneteenth（2026-06-19）**，不可沿用。
- **AI 權限**：AI 只負責讀網頁並把快報寫到暫存檔；`git add`、commit、push 由腳本做，且只加入當天的 `reports/YYYY-MM-DD.md` 與 `reports/index.json`。這樣網頁內容即使夾帶指令（prompt injection），也碰不到 git 與其他檔案。

## 4. 內容、資料來源與抓不到時的處理

通則（優先於各項）：

1. 數字只寫實際讀到的值，每項附資料時間；讀不到就寫 `⚠️ 無法取得（來源）`，**不得估算、不得從新聞反推、不得沿用前一天的數字**。
2. 單一來源失敗不中斷整份報告。
3. 資料時間明顯過期（例如期貨報價時間早於當天美東 00:00）要標示 `（資料時間 …）`，不當作最新值。
4. 文末「資料來源」只列本次實際讀取成功的來源。

### 4.1 各項細則

**1. 頭條**：只取過去 24 小時內、與美股大盤、Fed／利率、重大個股事件、地緣政治／關稅、能源／半導體／AI 產業相關的新聞；同一事件多來源只留一則；目標 5–8 則，每則一句話（≤ 40 字）＋來源名稱與連結。已放進第 2 項的經濟數據不重複列。

**2. 經濟數據**：

- 篩選：`country = USD`、`impact` 為 `High` 或 `Medium`、日期為當天美東日期；排除 Treasury Budget、Business Inventories、Redbook。
- **與舊 skill 不同之處（已驗證）**：
  - 日期格式是 `MM-DD-YYYY`，不是 `Mar 20, 2026`。
  - 時間是 **UTC**，不是美東時間（ISM Manufacturing PMI 標 `3:00pm`＝美東 10:00 EST）。輸出時換算成美東與台灣時間。
  - XML **沒有 `<actual>` 欄位**，無法用它判斷已公布或取得實際值；實際值改從日曆網頁取，取不到依上表處理。
  - `ff_calendar_nextweek.xml` 回 **404**；因為只在交易日當天執行，只讀 thisweek 即可。
- 名稱用舊 skill 的中文對照表，對照不到保留英文。

**3. 亞太指數**：美東 09:00 時亞太當日交易已收盤，這裡「早盤」解讀為「亞太當日交易的收盤結果」。每項列收盤值、漲跌點數與百分比、報價時間。指數清單：日經 225、韓國 KOSPI、台灣加權、香港恆生、上證綜合、澳洲 ASX 200。

**4. 期貨**：S&P 500、Nasdaq 100、道瓊期貨，列報價、漲跌點數與百分比、報價時間與合約月份。

**5. 美元指數**：ICE U.S. Dollar Index，列報價、漲跌、報價時間。

**6. 重點美股**：定義待決定（見文末）。不論哪種定義，每檔列代號、價格或漲跌幅、資料時間；寫原因時要能對應到第 1 項或來源連結裡的新聞，找不到原因就不寫原因。

**7. 復盤**：

- 讀 `reports/` 中日期早於今天的最新一份報告。
- 寫前一交易日三大指數收盤與漲跌。
- 對照前一份報告：當時「待公布」的經濟數據若能取得實際值，列出；當時列的重點美股，列前一交易日收盤漲跌。取不到的照通則標示。
- 1–3 句總結前一交易日主要驅動因素，必須能對應到第 1 項或附連結的新聞。

### 4.2 報告格式

```markdown
# 美股盤前快報 2026-11-03（週二）

> 產生時間：美東 09:0X EST／台灣 22:0X ｜ 產生者：Claude 或 Codex ｜ 今日開盤 09:30 ET（台灣 22:30）

## 1. 重要美國市場頭條
## 2. 今日美國經濟數據
## 3. 亞太股市
## 4. 美股期貨
## 5. 美元指數
## 6. 重點美股
## 7. 前一交易日復盤
## 資料來源
```

早收日在開頭加註當日 13:00 ET 收盤。標題順序與文字固定，供腳本檢查。

## 5. 執行方式與時間

### 5.1 排程

- systemd user timer（TG VM 的 `agent` 已開 linger，systemd 259 支援在 `OnCalendar` 指定時區）：
  `OnCalendar=Mon..Fri *-*-* 09:00:00 America/New_York`
  - 夏令（EDT）＝台灣 21:00 啟動；冬令（EST）＝台灣 22:00 啟動，由 systemd 依時區自動切換，不手算。
  - 不設 `Persistent=true`：VM 關機錯過就不補跑，避免開盤後才發出盤前報告。
- 時間預算（美東）：
  - 09:00 啟動，腳本先判斷交易日，非交易日直接結束並記錄。
  - 09:00–09:15 Claude 產生，逾時強制結束。
  - Claude 失敗（非零結束、逾時或格式檢查不過）→ 改用 Codex，限時到 09:24。
  - 09:25 前完成 push；超過就**不發布**，只留記錄（逾時的盤前報告沒有用途）。
  - GitHub Pages 部署約 1 分鐘（未驗證），目標 09:30 前網站可見。
- 不和 Telegram bot 搶同一個對話：排程用獨立的一次性呼叫（`claude -p`、`codex exec`），不經過 bot 的 session。

### 5.2 包裝腳本 `bin/run-brief` 步驟

1. 取得目前美東日期；查 `data/nyse-calendar.json`，休市或週末就結束。
2. 取得檔案鎖，避免重複執行；當天報告已存在就結束（不覆寫）。
3. `git pull --ff-only`；失敗就停止並記錄，不自行解衝突。
4. 用 `prompts/brief.md` 與前一份報告路徑組成指示，呼叫 Claude，輸出到暫存檔。
5. 格式檢查（見 6.2）；失敗改呼叫 Codex 重做一次。
6. 通過後移到 `reports/YYYY-MM-DD.md`，更新 `reports/index.json`，只 add 這兩個檔，commit message `brief: YYYY-MM-DD (claude|codex)`，push 到預設分支；push 失敗停止並記錄，不 force。
7. 記錄寫到 TG VM 的 `~/.local/state/cyhUsPremarketBrief/YYYY-MM-DD.log`（含用了哪個 AI、各來源成功與否、耗時）。

### 5.3 須先確認的執行環境（未驗證）

- 排程中的 `claude -p` 與 `codex exec` 是否都拿得到 Brave 無痕瀏覽工具（`claude mcp list` 目前沒列出 brave；Codex 設定只看到 `node_repl`）。拿不到就要在腳本中指定 MCP 設定。
- Claude 額度用盡時 `claude -p` 的結束碼與訊息；腳本用「非零結束或格式不過」判斷改用 Codex，不依賴特定訊息文字。
- push 用既有的 `gh auth git-credential`（已確認 git 有設定，`gh` 已登入 cyhbench）；在 timer 環境下是否可用要實測。

## 6. 驗收條件

每條都可實際檢查；「連續 N 個交易日」指實際上線後。

### 6.1 網站

1. 用手機與桌面瀏覽器開 GitHub Pages 網址，不登入即顯示最新一份快報。
2. 可從清單切換到任一歷史日期，內容與 `reports/` 該檔一致。
3. 在一份測試報告中放入 `<script>alert(1)</script>` 與 `<img src=x onerror=alert(1)>`，頁面顯示為文字、不執行；`javascript:` 連結不可點。
4. `index.html` 引用的 CDN 都帶固定版本號。

### 6.2 報告格式（腳本自動檢查，人工可重跑）

5. 檔名日期＝美東日期，且該日在 `data/nyse-calendar.json` 中是交易日。
6. 依序含第 4.2 節的 9 個標題，文字完全相同。
7. 開頭一行含產生時間（美東與台灣）與產生者（Claude／Codex）。
8. 不含未替換的範本字樣（如 `X.XX`、`HH:MM`、`[`…`]` 佔位）。
9. 「資料來源」至少列一項，且每項都是本次實際讀取成功的（對照執行記錄）。

### 6.3 內容正確性（人工抽查）

10. 上線後連續 3 個交易日，每天抽 5 個數字（至少涵蓋期貨、美元指數、亞太指數各一），和來源頁面在報告記載的資料時間附近的值一致。
11. 同期間經濟數據清單與 ForexFactory 當天 USD High／Medium 事件一致，時間換算正確（美東、台灣各對一次）。
12. 故意讓一個來源失敗（例如在測試執行中把某個網址改成不存在），該項顯示 `⚠️ 無法取得`，其他項照常，資料來源清單不列該來源。
13. 刪除前一份報告後執行一次測試，復盤段落顯示「無前一份報告，略過復盤」。

### 6.4 排程與時間

14. `systemctl --user list-timers` 顯示的下次觸發時間，EST 期間為台灣 22:00。另用 `TZ=Asia/Taipei systemd-analyze calendar 'Mon..Fri *-*-* 09:00:00 America/New_York' --iterations=3 --base-time='2027-03-11 12:00 Asia/Taipei'` 檢查跨 2027-03-14（DST 開始）：03-11、03-12 為 22:00，03-15 起為 21:00。（2026-11-02 已在 TG VM 實測此指令得到上述結果。）
15. 用模擬日期執行腳本（提供覆寫日期的參數，只在測試用）：2026-11-26（感恩節）不產生報告；2026-11-27（早收）產生並註明 13:00 收盤；2026-11-28（週六）不產生。
16. 上線後連續 5 個交易日，每天 `git log` 的 commit 時間介於美東 09:00–09:25，Pages 網址在 09:30 前可看到當天報告。
17. 模擬 Claude 失敗（例如把 Claude 指令暫時指向會回非零的指令），報告由 Codex 產生，開頭註明產生者為 Codex，commit message 帶 `codex`。
18. 模擬兩者都失敗或超過 09:25：沒有 commit，執行記錄寫明原因。
19. 每次 commit 只包含當天報告與 `reports/index.json`。

## 7. 風險與限制

- 所有來源都是免費網頁，版面或網址隨時可能改；本規格的「已驗證」只代表 2026-11-02 當下可讀。
- 公開轉載報價：CNBC、Business Insider 的報價有延遲且有使用條款，公開網站轉貼數字可能不符其條款；本規格以「少量數字＋標註來源與時間＋附連結」降低風險，未做法律確認。
- 每個交易日消耗一次 Claude 額度（約一年 250 次）；Claude 用完時改耗 Codex 額度。兩者都用完的日子沒有報告。
- 數字正確性只能抽查，無法自動證明 AI 沒有誤讀。
- `data/nyse-calendar.json` 需在 2027 年底前補 2028 年，否則腳本會停止（刻意如此，不猜休市日）。

1. **「重點美股」的定義**（影響資料來源與內容方向）。選項：

   - B. 固定觀察清單（請提供代號），每天報盤前價格與相關新聞。
   - C. 當天盤前公布財報的重要公司。
   - 也可以組合，例如 B＋A。
2. **GitHub repo 名稱與公開範圍**：建議建立 public repo `cyhbench/cyhUsPremarketBrief`，網址會是 `https://cyhbench.github.io/cyhUsPremarketBrief/`。整個 repo 會公開，包含 `docs/requirement.md`、本規格、腳本與提示詞（不含任何秘密）。是否同意用這個名稱建立並公開？或要改名、或把文件放在別處？
