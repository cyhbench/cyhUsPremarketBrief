# 美股盤前快報 UI 設計

文件版本：1.0（設計提案）

日期：2026-11-02（Asia/Taipei）

設計：Codex；下一步：Claude 實作。

依據：[spec.md 第 3.1、4.4 節](spec.md)、[design.md 第 8 節](design.md)、目前的 `index.html`，以及本機 2026-11-02 dry-run 範例報告。本文件只定義 UI，不改寫上述文件、程式或報告；範例數字僅用來理解版型，沒有重新核對金融資料。本文的版面與樣式是實作設計，漲跌色制另列「待使用者決定」，不新增 spec 的已決定事項。

## 1. 設計方向與現況差異

將頁面做成「每天一份、適合手機閱讀的市場晨報」：以明確的報告日期、安靜的藍色識別、分層卡片、整齊數字與充足留白，建立閱讀節奏。保持七節原有順序，不增加行情儀表板、圖表、即時更新或 AI 摘要。

目前頁面是 860px 單欄，標題、引言與表格幾乎直接按 Markdown 預設排版；所有表格都橫捲，手機必須左右來回看。新設計分為三個視覺層級：

1. **頁首與報告導言**：站名、日期切換、報告日期、產生與開盤時間，先回答「正在看哪一天、什麼時候整理的」。
2. **七個內容區塊**：編號標籤、節標題、獨立白色／深色面板；手機以卡片閱讀，桌面以表格比較。行情數字只在可靠辨識欄位時強調。
3. **資料來源與頁尾**：可展開的來源清單、網站版本、報告產生時間與既有免責文字，保持可查證性。

不把未確認、過期或無盤前報價包裝成「即時行情」；不從內文推論多空、重要程度或漲跌原因。缺值與警告的視覺可見度不能低於正常資料時間。

## 2. 手機優先的版面

### 2.1 寬度與閱讀順序

| 項目 | 手機：小於 768px | 平板／電腦：768px 以上 |
|---|---|---|
| 頁面容器 | 滿寬，左右各 16px；320px 寬時也保留內距 | 左右至少 24px，容器最大 1120px 並置中；1024px 起左右至少 32px |
| 站台頁首 | 站名在上，日期控制下一列且滿寬 | 站名靠左、日期控制靠右，同一列；不夠寬即換列 |
| 報告導言 | 日期大標題在前，產生與開盤資訊逐行排列 | 日期在左，時間資訊可分兩欄；仍按原文閱讀順序 |
| 七個主區塊 | 全部單欄，按 1–7 排列 | 七節仍由上而下；各節內部用表格或多欄卡片，不把不同節塞進不等高的拼貼網格 |
| 區塊外距／內距 | 區塊相隔 24px，面板內距 16px | 區塊相隔 32px，面板內距 24px |
| 子卡片 | 單欄，卡片間 12px | 視各節規則呈現，間距 16px |

768px 是表格與卡片的切換基準；實際內容比預期寬時，桌面表格仍有局部橫捲保底。不依裝置名稱判斷，手機橫放與桌面縮小視窗也套用相同規則。

頁首與導覽不固定在手機畫面上，以免長標題與大字模式佔掉閱讀空間。提供可換行的節目錄：頭條、經濟數據、亞太、期貨、美元、Mag 7、復盤；使用固定節標題產生的頁內錨點。每個目錄項目至少 44px 高，不以一條看不見後半的橫捲標籤列承載導覽。桌面同樣使用這列目錄，不新增側欄。

### 2.2 首屏與視覺構圖

手機由上而下是：小型站名 →「報告日期（美東）」選單與「最新一份」按鈕 → 狀態提示（有需要才顯示）→ 報告日期大標題 → 產生時間、產生者與開盤資訊 → 七節目錄 → 第 1 節。內容依視窗自然延伸，不設定導言固定高度或滿版封面；目標是正常字級的 390px 手機首屏能開始讀到內容。

導言面板上緣使用一條 3px 藍色識別線，日期為主要視覺焦點，時間以標籤和值成組排列。七節以小型藍色編號「01」至「07」搭配原節標題；編號是裝飾，讀屏不重複朗讀。資料來源使用較安靜的分隔線，不另加第 8 個市場編號。

整頁是淡底色上的實心面板；內部資料列以細分隔線區分，不把每個儲存格都框成格子。避免大面積漲跌色底、厚重陰影、裝飾性行情圖或公司 logo。視覺識別完全由文字、線條、留白與本機樣式構成。

## 3. 字級、色彩與元件樣式

### 3.1 排版尺度

使用本機系統字型：`system-ui`、`-apple-system`、`BlinkMacSystemFont`、`Segoe UI`、`sans-serif`；不下載字型。數字使用等寬數字特性，保留原始小數位、正負號與千分位，不為排版四捨五入。

| 文字／元件 | 手機 | 電腦 |
|---|---|---|
| 站名 | 18px、600 字重 | 20px、600 |
| 報告日期主標題 | 28px、700、行高 1.3 | 36px、700、行高 1.25 |
| 節標題 | 21px、700、行高 1.4 | 24px、700、行高 1.4 |
| 新聞與一般內文 | 16px、400、行高 1.75 | 17px、400、行高 1.75 |
| 可辨識的報價主值 | 24px、600、行高 1.3 | 28px、600、行高 1.3 |
| 表格資料 | 16px、行高 1.6 | 16px、行高 1.6 |
| 標籤、時間、頁尾 | 14px、行高 1.6 | 14px、行高 1.6 |

字級以可隨瀏覽器設定縮放的相對單位落實；表中 px 是 16px 基準下的設計值。內文段落間距 12px，節標題與內容 16px，標籤與值 4–6px。長敘述在寬螢幕上限制到約 45 個中文字寬；表格可用完整容器寬。卡片高度由內容決定，禁止行數截斷、省略號、固定高度裁切與隱藏關鍵資訊。

### 3.2 淺色／深色模式

依 `prefers-color-scheme` 跟隨系統，不新增手動主題切換與儲存偏好。原生選單、按鈕、表格與狀態面板一併適配，避免只有背景變黑。

| 用途 | 淺色 | 深色 |
|---|---|---|
| 頁面底色 | `#F3F6FA` | `#0C1422` |
| 主要面板 | `#FFFFFF` | `#141F30` |
| 次級面板／表頭 | `#EAF0F7` | `#1C2A3E` |
| 主要文字 | `#152338` | `#EDF3FC` |
| 次要文字 | `#52627A` | `#ADBBD0` |
| 分隔線 | `#CFD9E6` | `#35465E` |
| 識別色／連結 | `#1757B8` | `#8DBAFF` |
| 注意文字／底色 | `#854600`／`#FFF3D6` | `#FFD18A`／`#372B18` |

面板圓角 16px、子卡片 12px、控制項 10px。淺色模式可加非常淡的單層陰影，深色主要靠面板色差與邊框分層。連結常態有底線；鍵盤焦點使用 3px 識別色外框與間隔，不以細灰線作為唯一焦點提示。按鈕／選單至少 44px 高，主要按鈕用識別色實底並搭配通過對比檢查的文字色。

這些是候選色票，Claude 實作時須核對實際組合：一般文字對比至少 4.5:1，大字至少 3:1，控制項邊界與焦點至少 3:1。細分隔線僅供裝飾，不能代替必要的控制項邊界。

### 3.3 漲跌顏色：待使用者決定

兩種做法均適用全站所有市場；不依個別市場混用，以免同頁的紅色有相反意義。以下只是比較與建議，**尚未選定，Claude 不得把建議當作使用者決定**。

| 做法 | 上漲 | 下跌 | 優點與代價 |
|---|---|---|---|
| A：台灣習慣 | 紅 | 綠 | 符合台灣讀者日常看盤習慣；與美國行情網站的顏色相反 |
| B：美國習慣 | 綠 | 紅 | 和美股資料來源常見呈現一致；台灣使用者需要轉換習慣 |

**建議 A**：主要讀者以繁中手機閱讀，台灣色制較直覺；但本服務是美股內容，B 也合理，因此交使用者選擇。此項狀態為「待使用者決定」；不新增 A/B 偏好設定功能。決定前可先實作其他版面，漲跌維持一般文字色並保留原始正負號，不暗中套用任一方案。

候選紅色為淺色 `#B42332`、深色 `#FF8A98`；綠色為淺色 `#13734B`、深色 `#62D6A3`。選定後才把上漲／下跌對應到紅／綠，並核對對比。零變動用次要文字色，缺值用文字警告，無法判斷則維持一般文字色。只有已知「漲跌點數／漲跌幅」欄位內可可靠辨識的帶正負號數值可著色；不把股價、經濟數據的預期／實際差異、新聞文字或任意負數自動解讀為漲跌。美金、百分比與數值均照原文；不自行補方向。

一律保留 `+`／`-` 或原有「上漲／下跌」文字，不讓顏色成為唯一線索。色制確定後在報告導言旁提供文字圖例，例如「漲紅／跌綠」；決定前不顯示已選定圖例。

## 4. 七個區塊的手機與電腦呈現

以下只靠固定節標題、Markdown 清單／段落與表格的表頭、列、儲存格分組。無法辨識時使用第 5 節的保底呈現，不能為了卡片樣式遺漏原文。

### 4.1 重要美國市場頭條

- **手機**：每個頂層清單項目是一張低對比底色的新聞卡，單欄排列，卡片內距 16px。完整保留摘要、發布時間、來源名稱與安全連結；不拆猜括號內哪段是時間。以整段 16px 文字為主，連結保有底線。
- **電腦**：768–1023px 仍單欄；1024px 起兩欄、逐列按原始順序排列，行內內容頂端對齊，不做瀑布流或按重要性重排。卡片高度可自然延伸。
- **理由**：新聞是敘述資訊，卡片比窄表格好讀；兩欄可利用寬螢幕，但不能裁掉來源。只讓明確的來源連結可點，不把整張卡片變成猜測的新聞網址。若報告實際給表格，手機以有標籤的逐列卡片呈現，電腦保留表格。

### 4.2 今日美國經濟數據

- **手機**：每筆事件一張卡，事件名稱優先；其餘以「原表頭：原儲存格內容」成對排列，時間兩欄、預期／前值／實際值最多兩欄，名稱和較長內容獨佔一列。320px 或放大字體造成擁擠時全部改單欄。不省略美東 EST／EDT、台灣日期、單位與任何額外欄位。
- **電腦**：完整表格，事件名稱靠左且允許換行；時間與數值可短行顯示，數字靠右，列內上下內距 14px。表頭用次級面板底色、列間細線。內容過寬時只在這張表內橫捲。
- **理由**：六欄以上表格不適合手機縮字；事件卡能在一個視窗內讀完，電腦表格便於跨事件比較。原文「實際值未取得」不能自行改成「待公布」或推論已公布；「今日無重大美國經濟數據公布」以正常說明面板顯示，來源失敗則以注意面板顯示，兩者不同。

### 4.3 亞太股市

- **手機**：每個指數一張卡，單欄；名稱在上，可靠辨識的報價放大，漲跌幅與之相鄰，資料時間和其他欄位逐行列出。無法辨識報價欄時保留全部表頭標籤，不挑一個數字放大。
- **電腦**：六個指數以完整表格對齊比較，名稱靠左、數字靠右，資料時間獨立一欄；不把六個指數濃縮成一條超出容器的 ticker。
- **理由**：手機以逐項閱讀為主，電腦以同欄比較為主。範例用「來源所列當日值」而非「收盤」，UI 必須保留原表頭與表後的最終收盤未確認警告，不改標「已收盤」，也不猜休市。

### 4.4 美股期貨

- **手機**：三張單欄報價卡，依序 S&P 500、Nasdaq 100、道瓊。名稱／合約月份完整顯示，再列報價、漲跌點數、漲跌幅、資料時間及原時區；不把名稱中的月份移除。
- **電腦**：三張等寬卡片並排，每張內部用標籤和值排列，延續手機資訊順序。每張允許多行，容器不足時回到單欄，不縮小文字。無可靠表頭時保留原表格並局部橫捲。
- **理由**：三個品項適合以大數字建立視覺焦點，合約與報價時間則防止誤讀。表格前後的過期資料說明保留在卡片群前後原位置，不能只留下亮眼價格。

### 4.5 美元指數

- **手機**：一張滿寬面板。表格輸入可按標籤顯示主值、漲跌與資料時間；**目前範例是段落**，因此整段以舒適行距呈現，沿用原有粗體強調，不以正規表示式從敘述抽取 101.78 或方向另造報價元件。
- **電腦**：同一張面板，段落限制閱讀寬度，表格輸入則可橫向排成標籤和值組。不與下一節併成同一排，以保留固定閱讀順序。
- **理由**：單一指標不需橫捲；段落內有「非即時值」等限定語，保留整段比抽取數字更可靠。段落模式下也不憑「下跌」文字套用自動漲跌色。

### 4.6 Mag 7

- **手機**：每家公司一張單欄卡片，公司／代號作標題，其餘每欄都有完整原表頭和值。原表若合併「今日盤前價格／相對前收漲跌幅」，整個儲存格保留，不拆猜價格與百分比。缺值文字換行顯示；日期、來源欄位值與無盤前報價不隱藏在摺疊區。
- **電腦**：保留完整公司比較表，列內距 14px，所有額外欄位也保留，超寬時局部橫捲。新聞清單維持在原表格之後，以一般新聞列呈現，不依公司名稱猜測配對到卡片。
- **理由**：手機要先看每家公司有哪些可用資料；電腦需要橫向比較。範例有「10/30 前一交易日收盤」與「來源 previous_day_closing 值」兩個不同欄位，不能合併或以後者補前者。整段資料日期警告保留在表前，盤後資料說明保留在表後。

### 4.7 前一交易日復盤

- **手機**：同一個節面板內依原文順序排列：說明 → 指數表轉成逐列卡片 → 對照說明 → 經濟事件表轉成事件卡 → Mag 7 對照與驅動因素文字。實際順序以原文為準，不為套模板重新排序。不同資料型態之間保留 20px 間距，必要時使用細分隔線。
- **電腦**：每張表各自呈現；指數與經濟事件分表保留，不合成一張表，也不硬塞左右兩欄。敘述段落限制閱讀寬度，來源連結仍在敘述內。
- **理由**：復盤包含多種表格與缺報情境，單一規格卡片會混淆。以各表自己的表頭配對，無法判斷類型時使用通用卡片／局部橫捲，完整保留「無前一份報告，略過對照」、缺少日期與無法確認因素等文字。

## 5. Markdown 美化邊界與表格保底

### 5.1 可可靠使用的結構

依 spec 4.4 的一個 H1、七個固定 H2 與「資料來源」H2 分節；辨識的是 Markdown 解析後的標題節點，不能把程式碼區塊中的文字當標題。頁內錨點由前端固定對照產生，不接受報告指定的 HTML、樣式或 ID。報告 H1 的資訊只呈現一次作為頁面主標題，站名另用一般文字，不造成重複大標題。

只搬移已安全渲染的內容節點或以文字建立標籤，沿用第 8 節安全規則。表頭比對可忽略多餘空白，已知同義表頭須列明對照；遇到未知表頭時按原文當標籤，不靠欄位位置猜意義。例如「報價」可強調，但「來源所列當日值」不得改成「收盤」。不需要理解欄位意義的通用卡片仍可逐列保留全部資料。

本版可用的表頭對照如下；它們只決定排版用途，顯示時仍保留原表頭，不把同組文字改成同一名稱：

| 排版用途 | 可辨識表頭 |
|---|---|
| 卡片名稱 | 頭條表的「摘要」「頭條」；經濟表的「事件」；行情表的「指數」「公司」「期貨」「期貨／合約月份」「指標」 |
| 可放大的主值 | 「報價」「收盤」「收盤值」「來源所列當日值」；最後一項仍明示是來源值，不能改稱收盤 |
| 可辨識漲跌欄 | 「漲跌點數」「漲跌幅」；混合價格／百分比的欄位不在此列 |
| 一般標籤和值 | 其餘所有表頭，含帶日期的收盤欄、時間與混合欄；完整保留，不推測語意 |

同一張表若有多個名稱或主值候選，改用通用卡片，不自行挑一個。已知表頭之外不做模糊語意比對。

每張表獨立處理，不假定一節只有一張表。表前、表間、表後的文字、清單、引用與缺值說明均依序保留。原本只有條列／段落的節也有節面板與排版，不為符合 UI 補造表格或行情數字。

### 5.2 卡片轉換與橫捲規則

- 單層表頭、每列欄數一致時，手機把每個資料列轉成卡片；每個儲存格都帶原欄名。只有可靠辨識的名稱／事件欄可提升成卡片標題，其餘按原欄順序呈現。標籤必須是真正可被讀屏讀到的文字，不只用樣式產生。
- 缺表頭、重複／空白表頭、欄數不一致，或無法保持一對一對應時，整張表保留表格形式並放入局部橫捲容器，不丟欄、不猜標籤。不能因轉換失敗讓整節消失。
- 橫捲容器上方顯示「左右滑動查看完整表格」，僅確實溢出時出現；容器可用鍵盤聚焦、具區塊名稱，聚焦後能以方向鍵捲動。右側淡陰影提示尚有內容，捲到底時消失；文字提示不能被陰影取代。
- 全頁不能橫向捲動。卡片、表格外框與其父層都可縮到容器內；禁止用整頁隱藏水平溢出的方式掩蓋被裁掉的表格。只有表格自己的容器橫捲，不在容器兩端放遮住數值的固定裝飾。
- 長公司名、事件、網址、程式碼樣式文字與缺值說明允許換行；在卡片中整段長數值也有緊急換行保底，不強制整個儲存格不換行。表格則可保留短數值完整單行，由局部橫捲承接寬度。
- 一份資料只保留一套可存取呈現；不要把桌面表與手機卡片同時交給讀屏朗讀。桌面表保有表頭與資料格關聯，手機卡片保有名稱、標籤、值與來源連結的關係。

### 5.3 資料來源

放在第 7 節之後，以原生可展開區塊呈現，預設收合，摘要為「資料來源」。若能從頂層清單項目可靠計數，可附數量；否則不猜。展開後所有來源逐項完整顯示，長網址可換行，不以省略號遮住，也不自動把裸網址轉成未經檢查的連結。手機／電腦皆單欄，保持容易逐一核對。來源正文仍套用與報告相同的安全限制。

## 6. 日期切換與狀態畫面

### 6.1 日期控制

使用有明確標籤的原生選單「報告日期（美東）」，最新在前，只放清單中經實際日期驗證的日期；旁邊有「最新一份」按鈕。手機選單佔滿一列，按鈕可獨立下一列；桌面並排。選單不提供無報告的日子，不另加日期輸入器或日曆套件。「最新」代表清單最新一份，不保證是美東今日。

沿用 `#YYYY-MM-DD` 的日期連結，支援直接開啟、切換及瀏覽器上一頁／下一頁。頁內目錄依另一組固定區塊 ID 捲動定位並把鍵盤焦點移到該節標題，**不覆寫網址中的日期片段，也不新增歷史紀錄**，避免重整後遺失所選日期。非日期片段不作為報告路徑。初始化時若明確的日期片段不在清單中，回到最新一份，並以文字提示「找不到指定日期，改顯示最新一份」。

切換後立刻清除前一份本文、產生時間與相關提示，顯示新日期的載入狀態，保留可用日期選單；不要讓 A 日內容留在 B 日標題底下。只有最後選擇的回應可更新本文、提示、頁面標題與頁尾。載入成功後可將閱讀位置回到報告導言，但不強制搶走選單的鍵盤焦點。

### 6.2 狀態配置與文案

所有狀態沿用同一頁首與頁尾，主要訊息出現在原報告位置，帶明確標題、說明及適用動作。頁面上的操作只重讀同站靜態檔，不觸發產報或補報，不做輪詢與自動刷新。

| 狀態與可用證據 | 畫面與文案 | 操作與注意事項 |
|---|---|---|
| 首次載入清單 | 「正在載入報告清單…」，導言和內容位置放 2–3 塊靜態骨架 | 日期選單停用；讀屏只朗讀一次狀態，骨架不朗讀 |
| 切換／首次載入某日報告 | 「正在載入 YYYY-MM-DD 的快報…」與靜態骨架 | 日期選單可用；舊本文與舊產生時間不殘留，最新一份按鈕仍可選其他日期 |
| 成功顯示美東今日報告 | 顯示正常導言與七節；註明「盤前快照」 | 不加「即時」或行情更新倒數 |
| 成功顯示歷史報告 | 導言前提示「正在查看 YYYY-MM-DD 的歷史快報；美東今日為 YYYY-MM-DD」 | 可按「最新一份」；日期不同不算載入錯誤 |
| 最新一份不是美東今日 | 注意面板：「最新可用報告為 YYYY-MM-DD；美東今日為 YYYY-MM-DD，今日報告尚未發布或未產生」 | 可手動「重新整理清單」；不憑日期斷言正在產生、故障或休市 |
| 清單有效但 reports 為空 | 空狀態面板：「尚無報告」「發布後可在這裡閱讀每日快報」 | 日期停用，提供「重新整理清單」 |
| 清單 404 | 「尚無報告清單」「可能尚未發布，請稍後重試」 | 與有效空清單區別，不能斷言從未產生報告；日期停用，可重試 |
| 清單已列某日，但報告檔 404 | 注意面板：「報告更新中」「YYYY-MM-DD 已列入清單，但檔案暫時無法取得，可能仍在部署或檔案缺漏」 | 「重試此日期」「重新整理清單」；日期仍可用，不保證等待即可恢復 |
| 清單網路／非 404 HTTP 失敗 | 錯誤面板：「讀取報告清單失敗」「請檢查連線後重試」 | 日期停用，提供「重試」；不顯示「尚無報告」 |
| 清單 JSON／schema／日期不合法 | 錯誤面板：「報告清單格式不合法」 | 提供「重試」，不拿無效資料建立選單；可用日期須依既有驗證規則取得 |
| 單份報告網路／其他 HTTP 失敗、空本文 | 錯誤面板：「讀取報告失敗」「暫時無法載入 YYYY-MM-DD」 | 「重試此日期」，日期仍可用；404 走更新中狀態 |
| 本文日期不符或無法安全處理 | 錯誤面板：「報告內容與日期不符」或「報告格式無法顯示」 | 保留日期選單與重試，不把錯日內容顯示成所選日期；僅表格美化失敗時使用保底而非整份失敗 |
| 單一來源缺值／無盤前報價 | 報告正常顯示，原位置保留完整缺值文字；警告用注意色 | 不把整份報告換成錯誤畫面，不用 0 或舊價填空 |
| 版本檔失敗 | 頁尾顯示「網站版本：無法取得」 | 不影響正文，不增加全頁錯誤面板；下次重新載入再讀 |

重試期間只暫停同一個重試按鈕並標「重試中…」，失敗後可再次操作。重試清單時保留使用者原日期（若仍有效），否則回到最新並提示；原有日期列表仍可用時不必因重讀清單暫停日期選擇。請求結果同樣須避免過期回應覆蓋較新的選擇。

載入區以 `aria-busy` 表達忙碌，狀態採適度的即時朗讀；錯誤只公告一次，不反覆彈窗。無需用旋轉動畫製造持續更新感；支援減少動態效果設定，不做閃爍骨架。

## 7. 頁尾版本與資料產生時間

頁尾與報告之間留 32px／桌面 48px，使用細分隔線。手機分行、桌面可並排；14px 次要文字必須有足夠對比。

- **網站版本**：從 repo 根目錄的 `VERSION` 以同站相對路徑讀取，使用與其他資料相同的 `no-store` 策略。內容去除首尾空白後當純文字顯示；空白、檔案不存在、網路或 HTTP 失敗時一律顯示「網站版本：無法取得」。不從 commit、日期、文件版本或 AI 本文猜版本；不把版本字串放進 HTML、網址或腳本。
- **資料產生時間**：標籤為「資料產生時間（報告）」；值取所選報告開頭的產生時間行，保留美東 EST／EDT 與台灣日期時間。這是報告彙整快照時間，各行情實際資料時間仍以其所在列／段落為準；不使用下載時間、頁面開啟時間或部署時間代替。
- 能可靠讀出完整產生時間時，同時出現在導言與頁尾；讀不出則保留原開頭資訊，頁尾寫「資料產生時間：未能辨識，請見報告開頭」。載入中顯示「資料產生時間：載入中」，無報告或失敗時顯示「資料產生時間：—」。切換日期時一併清除舊值。
- 下方保留既有文字：「報告為 AI 於美東 09:00 起彙整的快照，數字可能延遲或有誤，僅供參考，不構成投資建議。」

## 8. 純靜態與安全限制

沿用 [design.md 第 8 節](design.md) 的全部安全限制；以下是套用到新 UI 的邊界，不降低原要求：

- 網站維持單一 `index.html` 檢視器，資料是同站靜態檔，不新增後端、API、登入、分析追蹤或報價請求。
- **不引入外部資源或 CDN**。現有頁面從 jsDelivr 載入 `marked@4.3.0`，與本次限制不符；建議將同版本解析器內嵌於頁面並保留授權說明，CSS、裝飾與識別也都在頁內。這是交給 Claude 的相依調整，本次不下載或修改解析器。spec 的舊 CDN 允許條款在本次 UI 範圍依使用者較嚴格的指示處理，版本仍鎖 4.3.0。
- 報告原始 HTML 一律跳脫成文字，含事件屬性與 SVG；不能先執行再清除。卡片標題、表頭標籤、狀態、版本與產生時間皆以文字或已安全處理的節點呈現，不能用字串拼接重新引入不可信 HTML。
- 連結解析後僅允許 `https:`，拒絕帳密、控制字元與其他不安全網址，文字與屬性各自正確跳脫；新視窗帶 `noopener noreferrer`。使用者主動開啟合法來源連結是允許的，不代表頁面可自動載入來源資源。
- Markdown 圖片只顯示替代文字，不載入外部圖片、公司 logo、favicon、iframe 或嵌入內容。不用外部字型、圖示包或圖片完成視覺設計。
- 清單與報告用既有同站固定路徑讀取，日期驗證後才組成 `reports/YYYY-MM-DD.md`。不使用 AI 提供的網址、HTML 或清單任意路徑建立選單與請求。
- 保留 `no-store`；靜態站無法知道 AI 是否正在執行，也無法保證 CDN 即刻一致，狀態文案須遵守第 6 節的證據界線。只支援網址開啟，不承諾 `file://` 離線載入。
- 顯示報告原有美東與台灣時間，不依讀者裝置時區重解行情日期；只有判斷「美東今日」使用 `America/New_York`。
